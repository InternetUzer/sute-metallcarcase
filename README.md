# Металл-Каркас — независимый сайт

Сайт для строительства ангаров и складов, изготовления и монтажа металлоконструкций, бетонных работ и монтажа сэндвич-панелей. Собственный исходный код на Python/Flask, HTML, CSS и JavaScript. Работает на сервере владельца, без Megagroup и платного конструктора. Flask — библиотека приложения, а не сервис, владеющий сайтом.

## Что сделано

- Новая адаптивная главная, отдельные страницы услуг и зданий, галерея с фильтрами и увеличением фото.
- Переписанные тексты, индивидуальные title/description, canonical, sitemap.xml, robots.txt, семантическая разметка Organization/Service. Сохранение старых адресов и 301-переадресации.
- 239 изображений с 27 публичных страниц старого сайта сохранены локально; 16 наборов WebP для интерфейса. Реестр источников и единственной недоступной картинки — в `content/source/`.
- Четыре существующие 3D-модели Sketchfab: выбор, просмотр по нажатию, переход к заявке с выбранной моделью. Четыре дополнительных превью сохранены локально. Исходные GLB/GLTF в репозитории отсутствуют.
- Заявки с выбором работ, городом, размерами и файлами. Они сохраняются в SQLite; при настройке SMTP приходит уведомление.
- Панель владельца: заявки, клиенты, объекты, статусы, документы и их версии, обновления по объектам, контакты сайта, публикации с выбором имеющихся фото.
- Кабинет клиента: только собственные объекты и документы. Одноразовые приглашения и восстановление пароля.
- CSRF, ограничение запросов, хеширование паролей, защищённые загрузки, заголовки безопасности. На временном адресе индексация отключена.

## Новые инструменты владельца

- На странице объекта — импорт XLSX с плановыми и выполненными объёмами, ценами, сроками и датами счетов. Шаблон скачивается из админки. Предпросмотр и подтверждение защищают текущую таблицу от ошибочного файла.
- В админке — отдельный раздел «Фотографии»: загрузка JPG/PNG/WebP, оптимизация и выбор фото при публикации без GitHub. Хранение в постоянном DATA_DIR, включая резервную копию.
- [Обновление test.metalcarcase.ru в ISPmanager/Passenger](docs/TEST-HOST-UPDATE.md).

## Локальный запуск

Нужен Python 3.12 или новее. Для разработки:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m flask --app 'app:create_app' run --port 8000
```

Открыть `http://127.0.0.1:8000`. Данные сохраняются в `instance/` и исключены из Git. Без постоянного SECRET_KEY вход сбрасывается при перезапуске в режиме разработки. Для сохранения сессий задайте секрет через окружение. `.env` автоматически читает Docker Compose; при локальном запуске используйте переменные окружения.

Создать владельца (пароль запрашивается в терминале):

```bash
python -m flask --app 'app:create_app' create-admin
```

Вход: `/login`. После входа владельца открывается `/admin`. Добавьте клиента, передайте ему одноразовую ссылку, создайте объект. На странице объекта размещайте документы и обновления. Клиентская регистрация с публичным доступом отключена.

## Проверка

```bash
python -m pytest -q
node --check static/site.js
```

26 тестов проверяют публичные страницы, метаданные и изображения, заявки и вложения, защиту форм, изоляцию клиентов, парольные ссылки, публикации, редиректы и ограничение запросов. Это серверные проверки; окончательно проверьте мобильный интерфейс, реальную почту, HTTPS и просмотр Sketchfab на тестовом сервере.

## Запуск на своём сервере

Подробно: [docs/DEPLOY.md](docs/DEPLOY.md). В комплекте Docker Compose, Gunicorn и Caddy с автоматическим HTTPS. **GitHub Pages не подходит**: кабинет, документы и заявки требуют серверной части.

```bash
cp .env.example .env
# Заполнить .env: домен, секрет и SMTP.
docker compose up -d --build
docker compose exec web flask --app 'app:create_app' create-admin
```

Старый сайт и DNS этой разработкой не изменяются. Сначала запустите копию на временном адресе, затем выполните [план перехода](docs/MIGRATION.md).

## Редактирование

- [Контент и структура](docs/CONTENT.md)
- Тексты услуг, здания, FAQ, реквизиты и модели: `content.py`.
- Вёрстка: `templates/`; оформление и интерактивность: `static/site.css`, `static/site.js`.
- Галерея: `content/gallery.json`; изображения интерфейса: `content/assets.json`.
- Исходные изображения: `static/images/original/`; оптимизированные: `static/images/web/`.
- Приватные данные и документы: каталог `DATA_DIR`, никогда не публичный GitHub.

Сайт не содержит выдуманных цен, сроков, адресов выполненных объектов или гарантированных SEO-результатов. Географию работы, актуальные контакты и документы по обработке данных нужно подтвердить перед публичным запуском. Аналитика и счётчики без предоставленных идентификаторов не включены.
