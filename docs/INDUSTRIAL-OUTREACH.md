# Внутренний реестр промышленных парков

Раздел `/parks` — общая карта, карточки парков, контакты и история выездов.
Рабочая ветка: `codex/industrial-outreach-m7-20261102`, PR #23. Установка разрешена
только на `test.metalcarcase.ru`; основной сайт и Прораб+ не изменяются.

## Доступ (решение владельца от 02.11.2026)

- Владелец входит своей учётной записью администратора и видит все данные.
- В `/parks/staff` владелец создаёт **один общий логин** для команды. Пароль
  вводится в форме, хранится только хеш. Пароли и рабочие ключи в Git не попадают.
- Новая роль `outreach` видит все парки, зоны, контакты и все отчёты, включая
  записи администратора. Можно добавлять контакты и отчёты. Автор записей общего
  входа отображается как «Сотрудники»; различить людей при общем входе нельзя.
- Общий вход не даёт доступа к `/admin`, `/admin/prorab`, `/cabinet`, клиентским
  проектам/файлам, управлению сотрудниками, настройке карты или импорту.
- Частичный уникальный индекс допускает только один общий аккаунт. Смена пароля
  увеличивает версию пользователя и завершает прежние сеансы команды.
- Старые роли `field` сохраняют прежнее ограничение зон для совместимости.
  Новая форма такие аккаунты не создаёт, существующие записи не удаляет.

## Карта, фильтры и мобильные экраны

Приоритет, зона и поиск применяются **только кнопкой «Показать»**. Карта и список
используют один серверный фильтр; поиск учитывает кириллицу. По умолчанию показан
приоритет A. Полный реестр — выбор «Все объекты» и «Все зоны» + «Показать».

На телефоне таблица становится карточками без горизонтальной прокрутки. Сохранён
один набор записей в DOM. Кнопки от 44 px, поля от 16 px, компактная шапка,
переходы к фильтрам/карте/списку и отчёту/контактам/истории. Дополнительные данные
о строительстве раскрываются отдельно. После сохранения отчёта открывается
история, контакта — раздел контактов; показано подтверждение сохранения.

На сенсорном экране по умолчанию один палец прокручивает страницу, два меняют
масштаб карты. «Двигать карту» включает перемещение одним пальцем, «Завершить»
возвращает прокрутку страницы. Сайт не запрашивает геолокацию сотрудника.

## Российская подложка: Яндекс Tiles API

Поддержан официальный бесплатный Tiles API, включая закрытые системы. Условия
проверены 02.11.2026; бесплатный лимит — 30 запросов тайлов в секунду.

1. Владелец получает **свой ключ Tiles API** в https://developer.tech.yandex.ru/.
2. Ограничивает его доменом тестового сайта (основной домен — только при выпуске).
3. В `/parks/map-settings` сохраняет ключ. С этого момента запросы подложки идут
   только на `https://tiles.api-maps.yandex.ru/v1/tiles/`.
4. Активация нового ключа может занять до 15 минут. Без сохранённого ключа остаётся
   прежняя рабочая подложка OSM; это переходное состояние, не завершённая замена.

Ключ находится в `settings.parks_yandex_tiles_key`, используется браузером на
закрытой карте. Он не отображается повторно в форме и не включается в публичные
страницы. Ограничение доменом на стороне Яндекса обязательно. Отчёты, персональные
контакты и заметки не передаются поставщику карты.

Leaflet 1.9.4 поставляется локально. Используется `projection=web_mercator`, иначе
тайлы Яндекса не совпадут с точками Leaflet. Для экранов с высокой плотностью
пикселей `scale=2`. Официальный логотип из `static/vendor/yandex-tiles/` показан в
углу карты, содержит ссылку на Яндекс. Загрузка тайлов начинается после подбора
масштаба по точкам, чтобы не делать две начальные загрузки. Недокументированные
серверы тайлов и внешний JavaScript не используются. При ошибке подложки видны
предупреждение, точки и список; скрытого переключения на другого провайдера нет.

Документация и условия:
- https://yandex.ru/maps-api/docs/tiles-api/quickstart.html
- https://yandex.ru/maps-api/docs/tiles-api/request.html
- https://yandex.ru/maps-api/docs/tiles-api/index.html
- https://yandex.ru/legal/maps_api/ru/ (п. 6.5)

## Данные и маршруты

Реестр `docs/industrial-outreach/industrial_parks_prospecting_import.json` содержит
117 кандидатов и 115 пар координат. SHA-256:
`f19771ff0c0dd7c8c615321e145890a9a224c8fa6b394d0b0a27be1be90d6be7`.
Повторный импорт обновляет только справочные поля по ID, сохраняя контакты,
отчёты, текущий статус и следующие действия. Импорт доступен только владельцу.

Координаты большинства объектов приблизительные, это не подтверждённые въезды.
Маршрут подписан «к ориентиру». Поиск по названию/адресу работает и без координат.
Обычные ссылки `https://yandex.ru/maps/` открываются приложением или браузером по
настройкам устройства; GPS запрашивают сами Карты. Кадастровый номер можно
сохранить в отчёте о выезде. Собранные командой данные не хранить в GitHub.

## Проверка перед выпуском

- `python -m pytest -q`, `node --check static/industrial-outreach.js`.
- Вход владельца и два независимых входа одного общего аккаунта, чтение общих
  отчётов и контактов, запрет доступа к админке/клиентским файлам.
- Кнопка «Показать» обновляет и карту, и список; изменение поля само не отправляет форму.
- Экраны 320/360/390/430/768/1024/1440 px: реестр, карточка, контакты, история,
  создание доступа и настройка карты. Нет переполнения страницы по ширине.
- Локальная проверка Яндекс выполняется с синтетическим ключом и имитацией ответа
  тайлов. Настоящую подложку проверить после ввода ключа владельца на сайте.

## Установщик тестового окружения

`scripts/deploy_parks_staging.py --root /var/www/u3653079/data` сначала проверяет копию базы и импорт. Добавление `--apply` устанавливает выпуск только на `test.metalcarcase.ru`. Установщик откажется работать с основной базой, другой конфигурацией или символической ссылкой вместо тестового пути.

Выпуск нужно распаковать в **отдельную постоянную папку** под `--root`. Passenger тестового сайта после установки импортирует код из этой папки; её нельзя удалять. Существующая тестовая база, учётные записи и файлы остаются в `metalcarcase-app/instance`. Основной `metalcarcase-production` и `www/metalcarcase.ru` не являются целями установки.

Перед изменениями создаётся закрытая папка `metalcarcase-parks-backup-*`: согласованная копия SQLite, конфигурация, прежний `passenger_wsgi.py` и static. Путь сохраняется в `metalcarcase-app/instance/parks-release.json`. Для отката кода восстановить прежний WSGI и static из этой копии и обновить `www/test.metalcarcase.ru/tmp/restart.txt`. Импорт добавляет таблицы и не удаляет результаты выездов; восстанавливать всю старую базу после начала работы сотрудников без отдельного решения нельзя, это потеряет новые записи.

Для ручного импорта из доверенной серверной консоли доступна команда Flask `import-parks <файл.json>` с той же валидацией, что и форма администратора. Загружать персональные записи сотрудников в GitHub нельзя.

**Публикация на основном домене и слияние PR требуют отдельного согласования владельца.**

## Перенос на основной сайт по разрешению владельца (02.11.2026)

Разрешение на production получено после проверки тестовой версии. Рабочая ссылка
команды — `https://metalcarcase.ru/parks`; без входа она ведёт на форму входа,
после общего входа открывается реестр. Пароль остаётся тем, который владелец
задал на тестовом сайте.

Порядок установки из проверенного отдельного выпуска:
1. `deploy_prorab.py --production <root>/metalcarcase-production --webroot <root>/www/metalcarcase.ru`
   проверяет исходные хеши production и манифест без изменений.
2. `promote_parks_data.py --root <root>` проверяет перенос на изолированной копии.
3. Та же команда с `--apply` делает отдельную резервную копию основной базы и
   транзакционно добавляет реестр, контакты/отчёты, существующий хеш общего пароля
   и ключ Tiles API. Аккаунты администратора/клиентов, SMTP, SEO, заявки и файлы не
   заменяются. Авторские ID сопоставляются с существующими аккаунтами.
4. `deploy_prorab.py ... --apply` сохраняет код, БД, конфигурацию, ключ/реестр
   квитанций и устанавливает только файлы манифеста. Код Прораб+ остаётся v24.
5. Проверить основные публичные страницы, вход команды, карту/фильтры и
   запрет `/admin` для сотрудников. Ключ Яндекса должен разрешать основной домен.

Повторный перенос данных после успешного первого не выполняется: маркер
`parks_initial_promotion` защищает новые production-записи от перезаписи.
При существующих данных CRM, конфликте логинов/ключей или неизвестном авторе
операция отказывается от изменений. Это однократный перенос, а не синхронизация
двух сайтов: после выпуска команда работает по основной ссылке.
