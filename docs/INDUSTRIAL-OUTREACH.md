# Внутренний реестр промышленных и логистических парков

## Задача
Три сотрудника посещают **парки целиком** — например, М7 Купавна, М7 Обухово, М12 Руднево, и аналогичные объекты в зоне исследования 50 км по прямой от центра Москвы. Номера отдельных участков, кадастровые номера и отдельные корпуса не создают дополнительных карточек.

Модуль внутренний и не затрагивает документы клиентов и «Прораб+».

## Маршруты и доступ
- /parks — карта, фильтры по приоритету и географической зоне, список и статусы.
- /parks/ID — единая карточка парка, контакты, журнал выездов.
- /parks/staff — только администратор: сотрудники и закреплённые зоны.
- /parks/import — только администратор: импорт JSON с публичными данными по паркам.
- /parks/map-data — закрытый картографический JSON; сотрудники видят только свою зону.

## Вход сотрудников
1. Администратор входит на сайт в /login, открывает /parks и раздел «Сотрудники и зоны».
2. Вводит имя и рабочий email сотрудника, выбирает зону. Создаётся новая роль field, отличная от client.
3. Передаёт одноразовую ссылку установки пароля лично. Ссылка действует 24 часа.
4. После входа сотрудник попадает в /parks и видит только свои парки.
5. Руководитель видит все зоны и результаты выездов.

## Что заполняет сотрудник
- Статус визита, дата и краткий итог встречи;
- имя, телефон, организация и должность контактного лица;
- собственник / лицо, принимающее решение, если удалось узнать;
- планируемое здание и ориентировочная площадь строительства;
- стадия проекта, существующий подрядчик;
- следующая задача и контрольная дата.

Контактов и отчётов может быть несколько, но карточка парка одна. История сохраняется в SQLite с автором записи.

## Подготовленный реестр
Данные первоначальной загрузки предоставляются отдельным рабочим файлом industrial_parks_prospecting_import.json (не содержат контактов, собранных на выезде). Достаточно загрузить его в форму на /parks. Повторный импорт обновляет публичные поля по стабильному ID, не удаляя историю посещений и добавленные контакты.

Реестр содержит кандидатов за границей радиуса и объекты с ориентировочной геопозицией. Адрес и въезд нужно подтвердить перед выездом. Телефоны операторов нельзя выдавать за телефоны собственников.

## Технология
Существующие Flask sessions, CSRF, хеширование паролей и восстановление доступа. Новая роль field. В каждом серверном обработчике проверяются роль и назначенная зона; API карты также закрыт. SQLite в DATA_DIR с новыми таблицами. Приватные страницы отвечают с noindex и no-store. Карта Leaflet с OpenStreetMap, запасная навигация через Яндекс Карты.

## Переход в Яндекс Карты
- В списке, карточке парка и всплывающей карточке на карте доступны обычные HTTPS-ссылки https://yandex.ru/maps/.
- Если указаны координаты, ссылка строит **автомобильный маршрут** от текущего местоположения: https://yandex.ru/maps/?rtext=~55.7500000%2C37.6200000&rtt=auto.
- Для каждого парка также есть поиск по **названию и адресу**. Это предпочтительно, когда въезд не подтверждён или координаты заданы лишь приблизительно.
- Координатная кнопка до подтверждения въезда подписана «Маршрут к ориентиру», чтобы не обещать точную навигацию к КПП.
- Платный API Яндекс Карт и специальные yandexnavi:// или yandexmaps:// ссылки не используются. Операционная система/браузер решает, открыть ссылку в приложении или в веб-интерфейсе. GPS доступ запрашивают сами Карты.
- Ссылки на Яндекс передают им адрес/координаты запрошенного объекта; сайт не передаёт Yandex номера телефонов и внутренние заметки о переговорах.

## Перед production
1. Выполнить python -m pytest -q tests/test_industrial_outreach.py tests/test_site.py.
2. Выполнить node --check static/industrial-outreach.js.
3. Проверить тестовое окружение с учётками трёх сотрудников, права доступа, корректность существующих /admin и /prorab.
4. Сделать резервную копию базы и пройти реальный сценарий с телефона.
5. Получить явное согласие владельца перед объединением PR или развертыванием на production.

# Проверка и установка на тестовый сайт (02.11.2026)

- Проверка выполняется поверх актуальной рабочей ветки `codex/messenger-buttons`, коммит `f99d46c` (Прораб+ v24). Код Прораб+ и приложение телефона не меняются.
- Карта и таблица используют один серверный фильтр; поиск учитывает кириллицу. Роль `field` не получает доступ к клиентскому кабинету и его файлам, даже при ошибочном назначении проекта этому пользователю.
- В `/parks/staff` можно повторно выдать одноразовую ссылку для установки пароля. Предыдущая ссылка перестаёт действовать. Логин — рабочая почта, пароль сотрудник задаёт сам; персональные учётные записи автоматически не создаются.
- Кадастровый номер доступен в форме выезда и истории. Повторный импорт реестра сохраняет контакты, отчёты и текущий статус.
- Leaflet 1.9.4 поставляется с сайтом, с лицензией и проверенными контрольными суммами. Внешняя загрузка JavaScript не нужна. Подложка использует OpenStreetMap; при её недоступности остаются точки, таблица и ссылки на Яндекс Карты.
- Исходный JSON: `docs/industrial-outreach/industrial_parks_prospecting_import.json`, 117 кандидатов, 115 пар координат. SHA-256: `f19771ff0c0dd7c8c615321e145890a9a224c8fa6b394d0b0a27be1be90d6be7`.

## Установщик тестового окружения

`scripts/deploy_parks_staging.py --root /var/www/u3653079/data` сначала проверяет копию базы и импорт. Добавление `--apply` устанавливает выпуск только на `test.metalcarcase.ru`. Установщик откажется работать с основной базой, другой конфигурацией или символической ссылкой вместо тестового пути.

Выпуск нужно распаковать в **отдельную постоянную папку** под `--root`. Passenger тестового сайта после установки импортирует код из этой папки; её нельзя удалять. Существующая тестовая база, учётные записи и файлы остаются в `metalcarcase-app/instance`. Основной `metalcarcase-production` и `www/metalcarcase.ru` не являются целями установки.

Перед изменениями создаётся закрытая папка `metalcarcase-parks-backup-*`: согласованная копия SQLite, конфигурация, прежний `passenger_wsgi.py` и static. Путь сохраняется в `metalcarcase-app/instance/parks-release.json`. Для отката кода восстановить прежний WSGI и static из этой копии и обновить `www/test.metalcarcase.ru/tmp/restart.txt`. Импорт добавляет таблицы и не удаляет результаты выездов; восстанавливать всю старую базу после начала работы сотрудников без отдельного решения нельзя, это потеряет новые записи.

Для ручного импорта из доверенной серверной консоли доступна команда Flask `import-parks <файл.json>` с той же валидацией, что и форма администратора. Загружать персональные записи сотрудников в GitHub нельзя.

**Публикация на основном домене и слияние PR требуют отдельного согласования владельца.**
