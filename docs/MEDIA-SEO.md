# Фотографии и SEO: панель владельца

После входа владельцем откройте `/admin/photos` или `/admin/seo`.

## Дерево фотографий

Общие изображения и превью моделей сгруппированы отдельно от карточек галереи и новых загрузок. В каждой записи есть миниатюра, подписи, адрес файла, список страниц использования и кнопка «Изменить». Если изображение не размещено, это показано отдельно. Дерево охватывает изображения интерфейса и галереи; неиспользуемый архив скачанных исходников `static/images/original` не является редактором активных блоков.

Общая фотография меняется сразу во всех перечисленных местах. У карточки галереи можно отдельно изменить фото, название, описание и ALT. Для нового файла доступны загрузка с устройства и выбор из библиотеки. Настройки сохраняются в SQLite, не в файлах Git; обновление кода не затирает их. «Вернуть исходное» восстанавливает файл и подписи встроенного блока. Прежние файлы загрузок сохраняются на диске, но после замены больше не выдаются публично, если не используются.

Название общей фотографии служит для навигации в админке, ALT описывает изображение, описание общего блока показывается при наведении. Название и описание карточки галереи отображаются посетителям. ALT, заданный для конкретного блока, имеет приоритет над ALT загруженного файла. Загруженная фотография, не используемая в публичных блоках, доступна только администратору.

## SEO

Для каждой публичной страницы: title, meta description, H1, запрет индексации и включение в sitemap. Пустое поле сохраняет исходный текст. Сниппет справа — приблизительный предпросмотр; поисковик может сформировать другой. Canonical автоматически использует `SITE_URL` и путь без параметров. Панель отмечает повторы и длинные метаданные; это подсказки, а не измеренные позиции.

Глобальные настройки позволяют поставить индексацию на паузу и добавить коды meta-подтверждения Google Search Console и Яндекс Вебмастера. Принимается только значение `content`, без HTML. Автоматической отправки sitemap, проверки владения или загрузки статистики из этих сервисов нет.

`SITE_INDEXABLE=0` и домены с префиксами `test.`, `staging.`, `preview.` блокируют индексацию независимо от галочек панели. `noindex` публикуется в meta и HTTP-заголовках. Публичные HTML-страницы не закрываются сплошным `Disallow: /`: поисковику нужен доступ, чтобы прочитать `noindex`. Приватные кабинеты и документы защищены авторизацией. Страницы с индивидуальным `noindex` не включаются в sitemap. На тестовом сайте карта доступна для проверки, но не объявляется в robots.txt.

Основание: [Google о noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing), [заголовках](https://developers.google.com/search/docs/appearance/title-link) и [картах сайта](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview).

## Обновление тестового хостинга

Перед установкой сохранить согласованную копию SQLite, всего DATA_DIR и текущей версии кода. Новые модули: `media_catalog.py`, `seo_panel.py`; также нужны `content/seo-defaults.json`, шаблоны, CSS и JS. Зависимости не изменены. Синхронизировать публичные копии CSS и JS на Passenger-хостинге, затем перезапустить приложение.

При старте автоматически добавляются таблицы `media_edits`, `photo_text`, `seo_pages`, `seo_settings`. Старые таблицы и записи не удаляются. При откате старый код не применит сохранённые SEO-настройки и размещение фото, но настройки останутся в БД; исходные файлы не перезаписаны. Резервная копия должна включать `media/`.

Боевой запуск — отдельный этап: актуальная копия данных, проверка основного домена/HTTPS, старых URL и редиректов, контактов и заявок; затем изменение SITE_URL/TRUSTED_HOSTS и SITE_INDEXABLE только для основного домена. Само сохранение SEO-настроек не изменяет DNS и не заменяет старый сайт.
