# Журнал работ «Прораб+» (`/admin/prorab` и `/prorab`)

Рабочий стол на компьютере для приложения «Прораб+» (Android): те же объекты, что в телефоне.

## Вход

- Владелец: вход на сайт → «Панель управления» → «Журнал работ (Прораб+)» (`/admin/prorab`, role = admin).
- Те, с кем владелец поделился папкой «Прораб+» на Яндекс Диске (Диск → «Поделиться» → «Пригласить в папку», право «Редактирование»): `/prorab` без входа на сайт (noindex, `Disallow: /prorab`). Страница без данных: каждый входит **своим** Яндексом и видит только то, к чему у его аккаунта есть доступ на Диске. Если общая папка у человека называется иначе — меню «Прораб+» → «Папка рабочего стола».
- Затем вход в Яндекс Диск: кнопка «Войти через Яндекс» открывает в новой вкладке `oauth.yandex.ru/authorize?response_type=token&client_id=…` приложения владельца «Прораб+» (тип «доступ к API», ClientID `637047bceacd46c9b55023e0658d2a6e` в `PRORAB_CLIENT_ID`, можно заменить `YANDEX_CLIENT_ID` / `settings.prorab_client_id`). Адрес возврата у такого приложения — `oauth.yandex.ru/verification_code`: Яндекс показывает ключ, человек вставляет его в кабинет (ключ или всю ссылку). Если у приложения адрес возврата на сайт, ключ подхватывается сам (в т. ч. из другой вкладки). Прежний вариант: Redirect URI `https://metalcarcase.ru/prorab` (после входа с `/admin/prorab` тоже возвращает на `/prorab`; для тестового сайта — `https://test.metalcarcase.ru/prorab`), права Яндекс Диска: `cloud_api:disk.read`, `cloud_api:disk.write`, `cloud_api:disk.info`) или ключ с Полигона Яндекс Диска.

## Как устроено

- **Папка рабочего стола закрепляется владельцем на сайте** (`settings.prorab_root`, по умолчанию `/Прораб+`): кнопка «Сделать … рабочим столом для всех» в кабинете под владельцем (`POST /admin/prorab/root`, admin + CSRF). Она подставляется всем браузерам и всем приглашённым (`data-root`). Своя папка в браузере — только если общая папка у приглашённого называется иначе. Если в папке объектов нет, кабинет ищет их на Диске (корень и первый уровень) и предлагает закрепить найденную папку. Приложение (с коммита после `331879c` в TECHNADZOR) подключает новые объекты в ту же общую папку.

- Общий кабинет всех объектов. **Рабочий стол — папка «Прораб+» на Яндекс Диске владельца** (туда же телефон по умолчанию подключает объекты: `Прораб+/<объект>`). Папки с `data/` показываются значками объектов; всё, что создано на рабочем столе (ярлыки на сайты `.url`, папки, Word, Excel, загруженные файлы), лежит прямо в «Прораб+». Объект из другой папки Диска можно добавить вручную («Добавить объект из папки») — список хранится в браузере.
- Ярлыки на папки Диска (вне рабочего стола): «Создать» → «Ярлык на папку Диска…» — папка открывается в проводнике кабинета, сама остаётся на месте; список — в `.prorab-desktop.json` (`links`).
- Окно объекта — значки «Сегодня», «Карточка объекта», «Журнал работ», «Календарь», «Ведомость», «Доп. работы», «Журнал приёмки», «Замечания», «Чертежи», «Финансы», «Техника и бригады», «Справочники», «Документы» (`<объект>/Документы`). Все разделы телефона, кроме «Состав объекта» (он хранится только в телефоне и в облако не уходит).
- **Сегодня**: план, просрочки, сроки по ведомости, ждущие приёмки, замечания со сроком, техника, люди, сделанное (как `todayView`).
- **Доп. работы** считаются сами из ведомости и журнала (как `extraWorksOf`): заведённые заранее (позиция с отметкой «доп. работа», `extraDate`), сверх плана, без плана, без позиции. Карточка — `extra_approvals` с постоянным id `extra:<позиция>`: пояснение, фото работы (`<id>:work`), кто согласовал (4 даты), примечание, подтверждение (фото), место на чертеже. Выгрузка в Excel.
- **Журнал приёмки** (`acceptances`): предъявить позицию («Закончено — на приёмку» и в ведомости), принято / не принято, кто принимал, замечания по приёмке (`remarks.acceptanceId`), «предъявить снова», отменить, история; выгрузка в Excel.
- Замечание можно поставить на чертёж: оно становится пометкой с теми же фото (как `RemarkPlacement`), в журнале замечаний — «Ч№».
- Пока открыта форма, ежеминутное обновление объекта ждёт (иначе правки формы могли потеряться).
- **Карточка объекта** (как в телефоне): название, адрес, участники, сроки, место для погоды («По адресу» — OpenStreetMap/Open-Meteo, «Где я сейчас» — геолокация браузера), свои поля (`project_fields`). Меняются только исправленные поля. Новый объект с компьютера сразу открывает карточку.
- **Справочники**: исполнители (имя, специализация, телефон, почта, заметка), виды работ и единицы, «Из каталога» (`catalog.js` генерируется из `Catalog.kt`: `web/tools/catalog.py` в репозитории приложения).
- **Чертежи**: PDF и DXF загружаются с компьютера в `<объект>/files/<id>.pdf|dxf` (как у телефона) и открываются в окне: масштаб колесом, сдвиг мышью, листы PDF, слои DXF, сохранённые виды (`drawing_views`), пометки (`drawing_notes`: статус, текст, исполнитель, срок, фото до/после). DWG переводится в DXF прямо в браузере библиотекой LibreDWG (та же, что в телефоне; `vendor/libredwg/`, сборка @mlightcad/libredwg-web 0.8.2, GPL-3, 10,8 МБ `.wasm`, загружается только для DWG); в объекте хранится DXF, как у телефона. Для этого на страницах журнала в CSP `script-src` добавлено `'wasm-unsafe-eval'` (разрешает только сборку WebAssembly, не `eval` для JavaScript). DXF разбирается `dxf.js` (перенос `DxfParser.kt`), рисует `viewer.js`; PDF — pdf.js 4.10.38 (Mozilla, Apache-2.0, `static/prorab/vendor/`, загружается только при открытии PDF).
- PDF, DXF и DWG на рабочем столе, в «Документах» и в папках Диска открываются как чертежи: в папке объекта — сразу как его чертёж с пометками (файл копируется в `<объект>/files/`, повторно не добавляется), в других местах — с выбором объекта; есть «Только посмотреть» (без пометок).
- Фото и видео на рабочем столе, в документах и в записях открываются в просмотрщике Яндекс Диска (новая вкладка). Можно открыть несколько объектов сразу; у каждого своя загрузка, сохранение и обновление раз в минуту.
- Постоянное хранилище журнала — Яндекс Диск. Браузер читает и пишет папку объекта (`data/*.json`, формат 1 с версиями полей, как в `cloud/SyncCore.kt` приложения). Для скачивания данных и чертежей используется ограниченный серверный маршрут `/prorab/download`: файловый сервер Яндекса может не разрешать CORS для домена сайта. Файл передаётся через временный буфер, закрываемый после ответа, и не добавляется в базу или каталог пользовательских загрузок сайта. Веб-версия — ещё одно устройство: пишет только свой файл `data/web-<id>.json`. Объединение правок — по полям: побеждает более поздняя правка поля; удаление — пометка `deleted = 1`.
- Настройки рабочего стола — `Прораб+/.prorab-desktop.json` (общие для всех компьютеров и приглашённых): фон и объекты из других папок Диска. Фон: готовые варианты или своя картинка (уменьшается до 2560 px, JPEG), картинка — `Прораб+/.prorab-desktop-*.jpg` (скрытые с рабочего стола), копия — в браузере. Показывается как `data:` (CSP `img-src 'self' data:` не меняется).
- «Новый объект» с компьютера: папка `Прораб+/<название>` и файл этого устройства; на телефоне — «Открыть из облака».
- Ключ Яндекс Диска хранится только в `localStorage` браузера владельца и уходит только на `cloud-api.yandex.net`; на сервер сайта не отправляется.
- Новые .docx/.xlsx собираются в браузере (`office.js`), правятся в Яндекс Документах (новая вкладка). Журнал за период выгружается в Excel (листы «По дням», «Итоги по дням», «Выполнено за период», «Объект») — скачать или сохранить в `<объект>/Документы/Отчёты`.

## Изменения сайта

- `app.py`: маршруты `GET /admin/prorab` (`protected(admin=True)`) и `GET /prorab` (без входа, noindex, `no-store`); только для них CSP `connect-src` дополнен адресами Яндекс Диска (`PRORAB_CONNECT`) и поиска места по адресу (`PRORAB_GEO`), а `Permissions-Policy` разрешает геолокацию своей странице (`geolocation=(self)`). `seo_panel.py`: `Disallow: /prorab` в robots.txt. Новых таблиц и миграций нет.
- `templates/prorab.html` (без встроенных скриптов и стилей), ссылка в `templates/admin.html`.
- `prorab_transfer.py`: `POST /prorab/download` для чтения временной подписанной ссылки Яндекс Диска и `POST /prorab/upload` для записи файлов до 20 МиБ. CSRF, ограничения частоты/времени/размера, только HTTPS и допустимые файловые хосты; IP проверяются, TLS подключается к проверенному IP. При скачивании перенаправления проверяются, при загрузке не допускаются. OAuth не принимается и не пересылается. Подписанная ссылка передаётся в теле POST, не в URL и не в журналах приложения. Этот файл также обязателен при установке.
- `static/prorab/`: `schema.js` (генерируется из Model.kt приложения: `web/tools/schema.py` в репозитории приложения), `catalog.js` (`web/tools/catalog.py`), `sync.js`, `model.js`, `disk.js`, `office.js`, `id.js`, `document-store.js`, `templates.js`, `dxf.js`, `viewer.js`, `app.js`, `prorab.css`, `vendor/pdf.min.js`, `vendor/pdf.worker.min.js`, `vendor/PDFJS-LICENSE.txt`, `vendor/libredwg/` (`libredwg-web.js`, `libredwg-web.wasm`, `COPYING.txt`, `README.txt`). Нужны и в приложении, и в webroot/static (сервер должен отдавать `.js` как JavaScript — pdf.js и LibreDWG подключаются как модули; `.wasm` лучше отдавать как `application/wasm`, иначе браузер загрузит его чуть медленнее, но тоже откроет).
- Необязательная настройка: `YANDEX_CLIENT_ID` (окружение) или `settings.prorab_client_id` — кнопка «Войти через Яндекс» (OAuth, Redirect URI = `https://metalcarcase.ru/admin/prorab`). Без неё вход по ключу с Полигона Яндекс Диска.

Технику, бригады и работу техники телефон начинает передавать через облако в версии приложения после коммита `9dd2810` (TECHNADZOR). Более старые версии принимают журнал, задачи и финансы, а записи техники и бригад с сайта пропускают (ничего не ломается).


## Проверка перед установкой (23.10.2026)

Проверен PR #9 на `f708c2287b69ca9e1d065f844de49575e3745ded`. Перед установкой исправлены:

- Вкладки больше не перезаписывают один и тот же файл устройства: Web Locks резервирует отдельный постоянный слот для каждой активной вкладки. Без Web Locks создаётся уникальный идентификатор сеанса.
- Черновики, названия объектов и настройки браузера разделены по `user.uid` Яндекс Диска. При смене аккаунта страница перезапускается, чтобы старые операции не использовали новый ключ.
- Правки сохраняются локально сразу после изменения; завершение предыдущей загрузки не удаляет новый черновик. Ошибка localStorage показывается пользователю. Сетевой сбой оставляет правки для повторной отправки.
- Обновление с Диска сохраняет экземпляр Project, на который ссылаются формы и незавершённые загрузки чертежей.
- CSP разрешает `blob:` для обработки локальных фотографий только на страницах Прораб+. Возврат OAuth проверяет одноразовый `state`; ручной ввод ключа остаётся доступен.
- Копирование, переименование и удаление с ответом 202 ждут подтверждения операции Диска. OAuth-заголовок отправляется только API Диска.

Добавлен `static/prorab/persistence.js` (он также обязателен в приложении и webroot). Версия ресурсов — 4.
Схема `schema.js` повторно сгенерирована из текущего `Model.kt` телефонного приложения: совпадение полное. Формат 1, `_v`, пути `data/*.json`, `files/` и правила версий сверены с CloudSync/SyncCore. Это проверка исходников, а не проверка фактической синхронизации на телефоне.
Файлы LibreDWG JS/WASM побайтово совпадают с официальным npm-пакетом `@mlightcad/libredwg-web@0.8.2`.

Установщик `scripts/deploy_prorab.py` использует `docs/prorab-manifest.json`: ожидает базу, указанную в `base_commit`, проверяет контрольные суммы, копирует всю статику в оба места, сохраняет SQLite и изменяемый код, отдельно hosting.json и passenger_wsgi.py. Сначала выполняет проверки на копии базы без SMTP, затем устанавливает файлы и перезапускает Passenger. Сам установщик не изменяет рабочую базу и пользовательские загрузки. При ошибке возвращает код, не откатывая заявки в базе.

```sh
~/metalcarcase-production/.venv/bin/python scripts/deploy_prorab.py --production ~/metalcarcase-production --webroot ~/www/metalcarcase.ru
# После успешной проверки:
~/metalcarcase-production/.venv/bin/python scripts/deploy_prorab.py --production ~/metalcarcase-production --webroot ~/www/metalcarcase.ru --apply
```

Выполнять из отдельной папки проверенного релиза. При отличии установленного файла от базы остановиться и сравнить изменения, не обходить проверку.
Откат кода: соответствие файлов лежит в `restore-map.json` резервной копии; восстановить изменённые файлы, убрать только созданные этим релизом файлы, обновить `webroot/tmp/restart.txt`. Базу и загруженные пользователями документы при обычном откате кода не заменять.
Проверки с реальным Яндекс-аккаунтом, приглашённым пользователем и телефоном требуют отдельных сеансов и остаются обязательной приёмкой после установки.

## Экономика собственника (шифруется кодом)

- Значок «💼 Экономика» на рабочем столе виден владельцу (страница `/admin/prorab`) и тем, у кого есть папка экономики. Также — «Пуск» и меню объекта.
- Папка — `/<имя рабочего стола> Экономика` в корне Диска (например `/прораб+ Экономика`), вне рабочего стола и его общих родительских папок. Файл — `economy.prorab.json`. Папку экономики не нужно открывать другим людям; нахождение вне рабочего стола само по себе не отменяет уже выданные права Диска.
- Шифрование в браузере (`vault.js`): случайный ключ данных AES-256-GCM; он хранится в файле, зашифрованный ключом из кода собственника и ключом из кода восстановления (PBKDF2-SHA-256, 600 000 итераций, своя соль). Код и расшифрованные данные — только в памяти вкладки; на Диске и через сервер скачивания сайта проходит только шифр. Код восстановления показывается один раз при создании; по нему можно войти и задать новый код. Сбросить код иначе нельзя.
- Экономика закрывается кнопкой «🔒 Закрыть» и сама через 15 минут без действий.
- Данные (`economy.js`): по объекту — сумма, номер и дата договора, бюджет по статьям финансов, график оплат (этапы), поступления, видимые только собственнику, заметки. Режим работы по уточнению владельца — один компьютер, одна открытая вкладка экономики. Web Locks не позволяют случайно открыть второй редактор той же экономики в другом окне этого браузера. Работа одновременно из разных браузеров/компьютеров не поддерживается.
- Сохранение (`economy-store.js`): перед закрытием формы правка записывается в зашифрованный черновик localStorage, привязанный к Яндекс uid и пути экономики. Кода, ключа и открытых сумм в нём нет. После подтверждённого чтением сохранения на Диске удаляется только отправленная версия черновика. Ошибка сети, блокировка экономики и закрытие вкладки не удаляют уже принятый черновик; при следующем входе он расшифровывается кодом и отправляется повторно. Не очищайте данные браузера до синхронизации. Если localStorage переполнено/недоступно, форма сообщает ошибку и остаётся открытой.
- Смена кода сообщает успех только после подтверждённой записи на Диске. При ошибке остаётся зашифрованная копия с прежним кодом. Код восстановления остаётся прежним. Смена кода меняет обёртку ключа данных, поэтому не отзывает доступ у человека, который ранее уже получил ключ или старую копию файла вместе со старым кодом. Для такого отзыва нужна отдельная ротация ключа данных.
- Защита от перебора зависит от сложности кода: минимум 8 знаков — технический предел, рекомендуется уникальный случайный пароль от 12 знаков или длинная фраза. Владелец должен использовать собственную учётную запись Яндекса; шифрование не защищает от удаления файлов тем, у кого есть доступ к аккаунту, или от чтения уже открытого экрана. Экспорт Excel сохраняется без шифрования по явному нажатию владельца.
- Расчёт: потрачено — расходы из «Финансов» объекта; выполнено — объёмы журнала × цены ведомости. «Принято по журналу» учитывает отдельные принятые записи и объёмы на дату предъявления всей позиции, без двойного счёта. Это оценка по ведомости, не сумма подписанных КС-2. Готовность ограничивается планом каждой позиции; дополнительные объёмы не закрывают другие работы. При неполных ценах применяется равный вес плановых позиций. Прогноз затрат — ориентир потрачено ÷ готовность (до 10% — бюджет), а сравнение со сроком предполагает равномерный темп. «Просрочка по графику» — этапы со сроком раньше сегодняшнего дня минус поступления; без графика показатель не определён. «Выполнено сверх оплаты» показывается отдельно и само по себе не означает наступивший долг. Сводка по всем объектам с итогами и выгрузкой в Excel.

## Фиксация данных — проверенный протокол v2

- У объекта есть раздел «Фиксация данных». Снимок содержит копии изменённых записей журнала, замечаний, приёмки и финансов объекта, SHA-256 состояния, ссылку на предыдущий снимок и отпечатки файлов. Копия состояния замораживается до первого асинхронного вызова. Физическое удаление строки записывается явно (`removed`).
- Яндекс Диск: `<объект>/.prorab-fixation/<устройство>/<номер>.json` и `<номер>.anchor.json`. Снимок сохраняется без перезаписи, читается обратно и только затем получает квитанцию. Ошибка загрузки не удаляет очередь файлов. Неотправленные квитанции повторяются до проверки 30-минутного интервала. Объект сохраняет исходную сессию Диска при смене аккаунта.
- Очередь SHA-256 новых фото, чертежей и документов хранится в браузере с привязкой к аккаунту, объекту и устройству. Для документов учитываются также JSON-метаданные участников, АОСР и КС. Старые файлы, ещё не попавшие в фиксации, автоматически не обходятся. Экономика собственника хранится отдельно и не включается в эти снимки.
- Сервер принимает только непрозрачные идентификаторы объекта/цепочки, номер и отпечатки SHA-256; строк журнала, финансовых сумм и содержимого файлов на сервере квитанций нет. `POST /prorab/anchor` фиксирует последовательность в отдельной приватной базе `instance/prorab-anchors.sqlite3`, затем выдаёт квитанцию HMAC-SHA256. Повтор того же запроса идемпотентен, подмена занятого номера/предшественника и пропуск номера запрещены.
- Подписаны поля `format`, `version`, `project`, `chain`, `seq`, `prev`, `hash`, `time`, `alg`, `key` в каноническом JSON. `POST /prorab/anchor/verify` проверяет пакеты до 100 квитанций и наличие в серверном реестре. `POST /prorab/anchor/heads` возвращает последние подтверждённые снимки по непрозрачному идентификатору объекта. Маршруты кабинета защищены CSRF и лимитами.
- Ключ независим от `SECRET_KEY`: `PRORAB_ANCHOR_KEY` (не меньше 32 знаков) либо автоматически создаваемый приватный `instance/prorab-anchor.key` (случайные 32 байта в hex, права 600). Ключ никогда не выводится в интерфейс или журнал. Установщик сохраняет ключ вместе с резервной копией и копирует существующую базу квитанций через SQLite backup. При утере ключа с уже существующими квитанциями новый ключ автоматически не создаётся: нужен исходный из резервной копии.
- Проверка сверяет цепочки и подписи, последние снимки с серверным реестром (в том числе удаление хвоста/целой цепочки), текущие байты зафиксированных файлов и текущее состояние журнала. Отсутствие связи, отсутствие снимков, непрочитанный файл или новые неподтверждённые изменения дают **незавершённую проверку**, а не зелёный успех. Различие текущего файла означает изменение после фиксации, само по себе не доказывает умышленную подделку.
- Экспорт: снимки, квитанции, отчёт с полнотой проверки и инструкция. Оригинальные фото/чертежи/документы нужно дополнительно сохранять с Диска: в архиве находятся только их отпечатки.
- Внешняя служба меток времени **не подключена**; непроверенное подключение по одному `PRORAB_TSA_URL` удалено. Квитанция удостоверяет получение отпечатка этим сайтом, не авторство записи, фактическое время выполнения работы или независимую метку времени. Подключение внешней службы требует отдельного выбора провайдера и проверки её подписи/цепочки доверия, отпечатка и nonce ответа. Самостоятельное решение о юридической доказательственной силе приложение не принимает.
- Цепочки телефона проверяются вместе с цепочками кабинета; ограничения старого протокола указаны ниже. Состояние синхронизированного объекта также попадает в снимок кабинета. Автоматическая фиксация производится после сохранения, не чаще раза в 30 минут; кнопка позволяет зафиксировать сразу.
- Проверки: удаление последнего снимка с квитанцией, удаление всей цепочки, подмена фото, повреждённый JSON, неверный номер/объект, разрыв связи, частичный файл, изменение данных во время загрузки, смена `SECRET_KEY`, потеря ключа, отказ диска при записи квитанции, повторы запроса, CSRF и работа кнопок интерфейса на имитации Диска.

### Решения владельца (24.10.2026)

- **Ключ квитанций — существующий.** Он создан при последней установке и включён в резервную копию. При обновлениях ключ не заменяется (установщик и `anchor_key()` уже не создают новый при существующих квитанциях). `PRORAB_ANCHOR_KEY` не задаём: смена источника ключа сделала бы старые квитанции непроверяемыми.
- **Нужна копия ключа и реестра вне хостинга.** Установщик делает копию `instance/prorab-anchor.key` и снимок `instance/prorab-anchors.sqlite3` (SQLite backup) только в резервную папку на этом же хостинге. Копию вне хостинга делает человек с доступом к серверу. Ключ и реестр — в одном наборе. Хранить в зашифрованном архиве, отдельно от Яндекс Диска с объектами: ключ позволяет подписывать квитанции. Обновлять копию после каждой установки и периодически, так как реестр растёт. Пока нет автоматической выгрузки — это ручной шаг приёмки.
- **Независимая служба времени пока не подключается** (`PRORAB_TSA_URL` не задаётся). Сначала — проверка совместной работы телефона и кабинета на живом Диске и сайте. Квитанция подтверждает только получение отпечатка нашим сервером. Выбор службы — отдельно, после проверки её условий и совместимости (формат ответа, доступность, условия использования). Страна сервиса или обозначение «ГОСТ» сами по себе пригодности не гарантируют.

## Исправление сохранения общего журнала (v15)

При создании папок сначала читается их тип; существующая папка не создаётся повторно. Параллельные запросы одной папки в одной сессии объединяются. Для ответа 423 предусмотрены до четырёх попыток с паузами 0,75 / 1,5 / 3 секунды; явный лимит загрузки и ошибки доступа не повторяются. Ответ 409 считается успехом только после подтверждения, что папка действительно существует.

Если сохранить общий журнал не удалось, сформированные байты Word остаются в окне до закрытия/обновления страницы: появляется кнопка «Скачать сформированный журнал». Сохранение на Диск при этом не объявляется успешным. Формат Word и существующие файлы не меняются.


## Передача файлов и сообщения об ошибках (v16)

Журнал Word, участники строительства и другие файлы до 20 МиБ передаются через ограниченный маршрут `/prorab/upload`. Это позволяет получить ответ загрузчика Яндекса даже при отсутствии CORS, вместо необработанного `Failed to fetch`. Временная ссылка и файл приходят в POST; OAuth остаётся в браузере. Сервер не сохраняет файлы проекта постоянно: временный файл запроса закрывается после передачи. Выполняется единственный PUT на проверенный адрес `uploader*.disk.yandex.net`, `uploader*.disk.yandex.ru` или `uploader*.dst.yandex.net`, путь `/upload-target/`; только публичный IP, проверенный TLS, без перенаправлений и автоматического повторения записи. Ошибки не раскрывают подписанные ссылки.

Файлы крупнее 20 МиБ по-прежнему передаются браузером напрямую; файловые серверы `*.dst.yandex.net` добавлены в CSP только кабинета. Общий лимит входящих запросов сайта 25 МиБ не менялся.

Ответ 423 теперь можно увидеть и на этапе передачи файла: блокировка записи отличается от явного лимита загрузки; 507 означает нехватку места. Правка сайта не снимает ограничения аккаунта или блокировки на стороне Яндекса и не меняет приложение на телефоне. При обрыве связи кабинет не заявляет, что запись выполнена. Исполнительная документация после передачи всё так же читается обратно и сравнивается побайтово; ответ загрузчика 202 сам по себе не подтверждает сохранение. Готовый Word при ошибке остаётся доступен для скачивания в открытом окне.

Проверки: безопасность адресов/DNS/перенаправлений, ограничения размера, CSRF и отсутствие OAuth в передаче, точные бинарные данные, ошибки 423/507/сети, отсутствие повторной отправки и обязательное обратное чтение документа. На настоящем аккаунте Яндекс Диска требуется отдельно проверить создание журнала и повторное сохранение участников; тестовый клиент имитирует ответы файлового сервера.

## Последовательные комплекты КС (v18)

Следующий номер определяется по сохранённым КС выбранного договора, включая отменённые номера. Запись `lastNumber` в файле участников больше не нужна: сбой её сохранения не возвращает нумерацию к 1. КС-2 и КС-3 печатают номер и даты из одной сохранённой записи комплекта.

Начальный период следующего комплекта начинается на день позже окончания последнего действующего КС; после сохранения форма переходит к следующему периоду. Кнопка «Следующий период» восстанавливает эти даты. Те же виды работ могут повторяться с новыми объёмами из журнала за другой период. Пересечение с уже сохранённым черновиком, повтор занятого номера и пересечение с предъявленным периодом останавливают формирование до загрузки файлов.

Ошибочный черновик можно отменить в реестре: отметка `cancelledAt` добавляется к записи, Word-файлы и прежние суммы сохраняются. Предъявленные акты этой кнопкой не отменяются. Для исправления сумм вручную в Word сначала отменяют исходный черновик, затем вносят итог через «Ранее предъявленная КС-2». В накопление КС-3 по-прежнему входят только предъявленные акты и текущий комплект; отмена и формирование не означают отправку заказчику. При предъявлении повторно проверяется актуальность накопления.

Проверены сценарии №1 → №2 с новыми объёмами одной работы, недоступный файл участников, устаревший номер в параметрах печати, защита от повторного периода, отмена без удаления Word и сохранность предъявленных актов. Реальные документы владельца не перезаписываются автоматически; ошибочные черновики нужно проверить в реестре.

Ввод дат не перерисовывает форму на событиях `input`/`change`: сегмент даты можно допечатать без потери фокуса. Таблица пересчитывается кнопкой «Применить период»; формирование и Excel читают текущие поля и требуют обе полные даты. Пустое окончание периода больше не заменяется сегодняшним днём молча.

После «Сохранить» формы участников строительства, настроек КС и общего журнала показывают «Сохраняю на Диск…», блокируют повторную отправку и после подтверждённого чтением сохранения выводят отдельное уведомление. Оно видно и на узком экране, не исчезает при перерисовке окна, закрывается вручную или через 8 секунд. АОСР показывает результат вместе с предупреждениями о метках шаблона. Ошибка остаётся в открытой форме с введёнными значениями; прежнее сообщение об успехе убирается перед новой попыткой. Проверены ожидание ответа, двойной клик, ошибка 423, ошибка проверки сохранённого файла и успешный повтор.

## Чистый чертёж, оси и углы (версия ресурсов 20)

В «Чертежах» кнопка «Новый чертёж» создаёт DXF с равномерной сеткой осей или чистое поле, если снять «Создать оси». Длина и ширина задаются в метрах, DXF — в миллиметрах; число осей в каждом направлении — 2–51. По длине оси обозначены числами, по ширине — буквами. Пересечения осей являются вершинами исходной геометрии и доступны для привязки. В чистом поле служебная рамка задаёт размеры, но её слой выключен.

«Оси и размеры» позволяет изменить собственную сетку позже. Параметры хранятся в комментарии самого DXF; новых таблиц и столбцов синхронизации нет. Для редактирования распознаётся только неизменённый файл генератора: внешний DXF с дополнительными правками не пересоздаётся по старому комментарию. Сохранение создаёт новый файл, проверяет его обратным чтением и лишь затем обновляет ссылку чертежа. ID, прежний файл, пометки и свои линии сохраняются; свои линии/пометки не растягиваются при изменении сетки. Изменившаяся за время открытой формы запись отклоняется. Ошибка отправки записи объекта отличается от успешной загрузки самого DXF.

В панели «Чертить» доступен шаг направления: свободно, 15°, 30°, 45°, 90° (Орто). Отсчёт идёт от осей чертежа, начало следующего отрезка — последняя поставленная точка. Ограничение действует для линий, ломаных, размеров и сторон контура. Для прямоугольника выбираются два противоположных угла без ограничения направления диагонали. DXF-привязка рассматривает только вершины на разрешённых направлениях: неподходящая ближайшая вершина не вытесняет подходящую и не вызывает ложный зелёный маркер. Alt отключает привязку к вершинам, сохраняя выбранный шаг.

«Замер угла»: точка на первой стороне → вершина → точка на второй стороне. Показывается меньший угол 0–180° с точностью отображения до 0,01°. Шаг направления при измерении отключён. Кнопка «Сохранить замер» добавляет стороны как polyline и подпись как text, поэтому телефон и экспорт DXF используют уже поддерживаемые типы. Подпись фиксирует результат измерения; это не динамическая геометрическая зависимость.

Проверки v20: модульные проверки геометрии, привязки, создания/редактирования DXF, ошибок загрузки и гонки старой/новой редакции входят в общий pytest. ## Состав объекта в кабинете (версия ресурсов 21)

Окно объекта «🧱 Состав объекта» — то же, что раздел «Состав объекта» в приложении (с базы 24 он синхронизируется
через облако): конструкции (`project_nodes`) и работы по ним (`work_bindings` → позиции `boq_items`).

- Дерево как в приложении (`CompositionTree.kt`): раздел → группа видов → конструкция (вложенные внутри) → работы;
  у веток — число работ, % выполнения (по стоимости, если у работ есть цены), плановая стоимость, работы без цены,
  «на приёмке» / «не принято». Работы удалённых конструкций — «Прочее → Конструкция в архиве».
- «+ Конструкция» (вид из библиотеки, название, место, вложенность), «Изменить» (вид не меняется; при новом названии
  автоназвания работ без истории следуют за ним), «Убрать» (только без вложенных и без работ, которые можно убрать).
- «+ Работы»: операции библиотеки для вида конструкции, участок (по умолчанию вся конструкция), объём и цена.
  Нельзя выбрать операцию дважды на одном участке и смешать комплекс с отдельными операциями одной группы.
  Создаются позиция ведомости (вид работ — по разделу операции, единица — по коду, ищутся без учёта регистра
  и лишних пробелов) и привязка (`id = itemId`, снимок шаблона, редакция).
- Работа с историей (есть «Сделано», приёмка, согласование доп. работы или «Закончено», как `itemsWithHistory`)
  не меняется и не убирается из состава — объём и цена правятся в ведомости.
- Библиотека `static/prorab/work-templates.js` — копия `app/src/main/assets/work-templates/v2.json` приложения
  (версия 2, 6 разделов, 40 видов конструкций, 91 операция). При новой редакции библиотеки в приложении скопировать заново.
- Логика без DOM — `static/prorab/composition.js`, тесты `tests/prorab/composition.test.js` и `composition-ui.test.js`.
- Новые файлы для установки: `static/prorab/work-templates.js`, `static/prorab/composition.js` (манифест не обновлялся).
