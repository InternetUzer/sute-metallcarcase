# Обновление test.metalcarcase.ru

Цель этого обновления — только `https://test.metalcarcase.ru`. Основной домен, DNS и сертификат не меняются.

При проверке 19 сентября 2026 года тестовый адрес отвечал HTTP 200 по HTTPS с заголовками nginx, Phusion Passenger и `X-Robots-Tag: noindex, nofollow`. Пути приложения, виртуального окружения и настройки Passenger в репозитории отсутствуют.

## Установка в существующее приложение ISPmanager / Passenger

1. В панели определите корень приложения, виртуальное окружение Python, файл входа Passenger, текущий `DATA_DIR` и способ перезапуска. Сохраните настройки и текущий commit. Не заменяйте локальный файл входа Passenger.
2. Закройте доступ на запись на время копирования. Сделайте согласованную резервную копию SQLite и всего `DATA_DIR` средствами хостинга или существующей Flask-командой `backup`. Команда должна работать с теми же переменными окружения, что использует сайт, иначе она может скопировать другую базу.
3. Получите одобренную версию из ветки `codex/excel-import-and-photos` или соответствующего merge commit, сохранив локальные настройки и файлы данных.
4. Установите `requirements.txt` в существующее виртуальное окружение приложения. Добавлены openpyxl, defusedxml и Pillow. Вместе с `app.py` нужны `project_sheets.py`, `photo_library.py`, новые шаблоны и обновлённый CSS.
5. Сохраните `SITE_URL=https://test.metalcarcase.ru`, `SITE_INDEXABLE=0`, прежние `SECRET_KEY` и `DATA_DIR`. Если настроен `TRUSTED_HOSTS`, он должен разрешать тестовый домен.
6. Перезапустите только Python-приложение тестового домена штатным способом ISPmanager/Passenger. При старте автоматически создадутся три новые таблицы SQLite и каталог `media/`. Существующие таблицы и записи не удаляются.

`DATA_DIR` должен быть постоянным, доступным на запись процессу приложения и находиться вне публичного каталога сайта. База, документы `files/` и фотографии `media/` остаются в нём при обновлении кода. Не создавайте nginx-alias или прямой статический доступ к этим каталогам: это обойдёт проверки доступа приложения.

Комплектный Docker Compose предназначен для отдельной установки с Caddy. Не запускайте его поверх работающего nginx/Passenger: он занимает порты 80/443. Dockerfile обновлён для новых модулей, но контейнеры на этом хостинге не проверялись.

## Проверка после установки

1. Войти владельцем → открыть объект клиента → «Импорт Excel» → скачать шаблон.
2. Заполнить лист «Работы». Загрузить файл: до подтверждения клиент видит прежнюю таблицу. Подтвердить и проверить результат под нужным клиентом.
3. Проверить ошибочный файл, отмену импорта и отсутствие доступа к объекту у другого клиента.
4. Открыть «Фотографии», загрузить JPG/PNG/WebP, выбрать фото при создании публикации и проверить галерею. До публикации фото видно только администратору.
5. Проверить существующие заявки, документы, вход и заголовок `X-Robots-Tag: noindex, nofollow`.
6. Сделать новую резервную копию: обновлённая команда `backup` включает `media/`. При восстановлении переносите его вместе с базой и `files/`.

## Правила импорта

Лист «Работы» содержит восемь столбцов: работа, единица измерения, плановый объём, выполненный объём, цена за единицу в рублях, начало работ, срок завершения, дата выставления счёта. Даты необязательны; объёмы и цена обязательны, допускается ноль. Формулы нужно заменить значениями. До 500 строк и 5 МБ. Пустой файл не очищает таблицу.

Предпросмотр доступен создавшему его администратору 30 минут. Подтверждение полностью заменяет таблицу одного объекта в одной транзакции. При изменении таблицы другим импортом подтверждение блокируется до повторной загрузки. Документы и обновления объекта не затрагиваются.

Фотографии: JPG/PNG/WebP до 10 МБ и 24 мегапикселей. Приложение проверяет содержимое, уменьшает до 2400 пикселей по длинной стороне и сохраняет WebP без исходных метаданных. Анимация не принимается. Публичная выдача доступна, пока фото используется хотя бы в одной активной публикации.

## Откат

Сохраните текущие данные, верните прежний код и перезапустите приложение. Новые таблицы SQLite можно оставить: прежний код их не использует. Прежняя версия не обслуживает `/media/`: перед откатом снимите публикации с новыми фото либо восстановите согласованную копию базы и файлов. Восстановление старой копии теряет последующие изменения — сначала сохраните их отдельно.
