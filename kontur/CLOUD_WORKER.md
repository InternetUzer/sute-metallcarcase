# Контур: серверный исполнитель

Статус: код подготовлен и проверяется на имитациях CLI. На боевом сервере
исполнитель ещё не установлен. Работа с реальными аккаунтами и сетевой доступ
OpenAI/Anthropic должны быть проверены на выбранном сервере до включения очереди.
Текущий REG.RU не подходит: ранее OpenAI вернул региональную ошибку, Anthropic — 403.

## Что переносится в облако

Сайт остаётся на существующем хостинге. Linux-процесс исполнителя соединяется с ним
по исходящему HTTPS, синхронизирует проекты и диалоги, атомарно забирает задание,
запускает официальные Codex/Claude Code и возвращает ответы в тот же диалог.
Роли, память, последовательный обмен ответами и импорт истории сохраняются.
Входящие порты на исполнителе для Контура открывать не нужно.
Исполнитель может работать на том же сервере, что и сайт, если окружение и доступ
к ИИ позволяют. Второй сервер не является обязательным требованием программы.
Текущая договорённость: сначала текущий сервер; другой сервер — только отдельное
решение для будущих подключений. Обнаруженные ограничения текущего хостинга
нужно устранить/проверить, а не считать покупку другого сервера согласованной.

На сайте доступны регистрация/отзыв сервера, статус связи и аккаунтов, выбор
исполнителя общей очереди, получение списка приватных репозиториев через GitHub
аккаунт исполнителя, обзор Issues/PR и явное клонирование выбранного проекта.
Файлы ноутбука в облако автоматически не копируются. Копия кода на сервере
независима; изменения веток, коммиты и отправка в GitHub — отдельные задания.
Повторная подготовка репозитория не делает pull/reset и не затирает файлы.

## Граница авторизации этой версии

Первый вход выполняется **в защищённом терминале сервера**, официальными CLI:

```sh
python3 -m kontur.worker login codex
python3 -m kontur.worker login claude
python3 -m kontur.worker login gh
```

Codex использует официальный device-code flow. Claude Code и GitHub CLI
используют свои браузерные подтверждения. Официальный CLI хранит свои токены
на сервере под отдельным пользователем. Контур не извлекает OAuth-токены
Codex/Claude и не пересылает их сайту или ноутбуку.

Кнопка «Вход на сервере» на сайте пока показывает эти команды, а не проводит
авторизацию внутри сайта. Встроенный запуск и подтверждение входа из веб-интерфейса
в эту поставку **не входят**. Это следующий этап после выбора и проверки сервера.
Перенос CLI в облако не гарантирует устранение региональной ошибки: доступ должен
работать и при подтверждении в браузере, и при запросах с сервера.

Официальные инструкции:
- https://learn.chatgpt.com/docs/auth
- https://code.claude.com/docs/en/authentication
- https://cli.github.com/manual/gh_auth_login

## Установка на подготовленный сервер

Нужен Linux с Python 3.11+, Git, официальными Codex CLI, Claude Code, GitHub CLI
и совместимой с выбранными CLI версией Node.js, если используется npm-установка.
Ресурсы выбирают по проектам: это исполнитель кода, а не локальная модель ИИ.
Работать следует под отдельным непривилегированным пользователем.

1. Обновить модуль `kontur` на существующем сайте обычным `kontur/deploy.py`,
   предварительно выполнив `--check` и сделав SQLite backup. При первом запуске
   добавляются таблицы `workers`/`worker_commands`; существующие записи остаются.
2. Разместить исходники этого коммита в `~/kontur-src` на Linux-сервере.
3. На сайте в «Подключения → Исполнение задач» создать ключ сервера. Это **другой**
   ключ, не ключ ноутбука. Выполнить на сервере:

```sh
cd ~/kontur-src
python3 -m kontur.worker pair --url https://metalcarcase.ru/kontur
python3 -m kontur.worker login codex
python3 -m kontur.worker login claude
python3 -m kontur.worker login gh
python3 -m kontur.worker doctor
```

Ключ вводится скрыто через `getpass`, без аргументов командной строки или чата.
Настройки/база находятся в `~/.local/share/kontur-worker`: каталог 0700, файлы 0600,
umask 0077. Linux-копия ключа защищена правами файлов, **не шифрованием**. Изолируйте
пользователя сервера и защищайте резервные копии; этот каталог и конфигурация CLI
не должны попадать в репозитории проектов.

4. Для первой проверки запустить `python3 -m kontur.worker run`. На сайте выбрать
   этот сервер для очереди; отправить отдельный тест каждому ИИ и общий диалог.
   Проверить отказ при недоступном регионе/аккаунте и поведение остановки.
5. В настройках проекта нажать «Подготовить репозиторий». Затем проверить работу
   с тестовой веткой и фактические GitHub-права; автоматическая публикация не включается.
6. После проверки установить службу пользователя:

```sh
mkdir -p ~/.config/systemd/user
cp kontur/packaging/kontur-worker.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now kontur-worker
```

Для работы после выхода из SSH администратор сервера включает linger для
выделенного пользователя: `sudo loginctl enable-linger USERNAME`.
Если CLI установлен в пользовательском npm/nvm-каталоге, добавить его фактический
абсолютный путь в `Environment=PATH=...` службы. Проверить доступность CLI именно
из окружения службы. Не копировать в конфигурацию серверные пароли и API-ключи.
Для повторного входа остановить службу, выполнить `login`, затем запустить её.

## Очередь, сбои и обратная совместимость

- Исполнитель выбирается для общей очереди на сайте. Смена запрещена, пока есть
  задания со статусом «Выполняется». Отозванный/отключённый сервер не заменяется
  ноутбуком автоматически; новые задания остаются в очереди.
- Захват задания и смена исполнителя используют транзакции SQLite, включая
  несколько WSGI-процессов. Повторный захват одного запуска отклоняется.
- Старый ноутбук 0.2 не может забрать облачное задание или записать ему ошибку
  отсутствующей локальной папки. Такие изменения сохраняются как конфликт;
  новая версия приложения заранее видит, что выбран сервер, и не пытается выполнять.
- После сбоя начатое задание помечается «Прервано»; внешние действия не повторяются.
  После обрыва связи ответы остаются в локальной базе исполнителя до синхронизации.
- Остановка через сайт доставляется при следующей связи (обычно до 8–10 секунд
  при исправной сети). При полной потере связи мгновенная остановка невозможна.
- Отключённый сервер виден как «не на связи» через 60 секунд. Наличие входа в CLI
  не гарантирует действующую подписку или доступность модели: это проверяет реальный запрос.
- GitHub-команды передаются не более одного раза; при потере ответа выдачи команда
  истекает, а не исполняется повторно. Перед повтором операции проверьте результат.
- Ключ сервера не даёт доступа к админке, созданию других ключей или изменению проектов
  через API; он читает контекст и пишет только результаты собственных запусков.

## Проверки

```sh
python3 -m unittest discover -s kontur/tests -v
node --check kontur/static/app.js
node kontur/tests/test_chat_import.mjs
python3 -m pytest tests/test_kontur.py
```

Тесты облачного диалога не обращаются к платным ИИ: ответы официальных CLI
заменены имитацией. До реальной проверки выбранного сервера это подготовленный
этап реализации, а не действующая автономная облачная установка.
