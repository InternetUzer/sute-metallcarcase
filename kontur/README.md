# Контур 0.1 — личное рабочее пространство

Windows 11 + `https://metalcarcase.ru/kontur/` на существующем Python-хостинге.
Один интерфейс: рабочий стол с папками проектов, боковое меню, окна проектов,
задачи, память, общий чат, роли Codex/Claude и история запусков.

## Windows

Готовые установщик и portable ZIP собираются workflow **Kontur Windows**.
Установщик не требует администратора; создаёт ярлык. Интерфейс открывается в
отдельном окне Microsoft Edge. Python входит в сборку PyInstaller.
Это первая версия оболочки на локальном HTTP-сервере, не встроенный WebView.
Закрытие окна оставляет исполнителя в фоне. Полный выход: Подключения →
«Завершить Контур». Повторный запуск открывает уже работающий экземпляр.

Запуск из исходников (Python 3.11+ без зависимостей):

```powershell
python -m kontur.desktop
```

Или `kontur/Start-Kontur.cmd`. Данные: `%LOCALAPPDATA%/Kontur/kontur.sqlite3`.
Локальный HTTP слушает только `127.0.0.1`; случайный порт, HttpOnly cookie,
защита Host/Origin, CSRF. Предпросмотр `--preview` — только для разработки,
никогда не использовать на обычном компьютере или публичном сервере.

## Первый запуск

1. Создать проект или выбрать репозитории через кнопку GitHub. Публичные
   репозитории доступны без входа; приватные — через `gh auth login` на ноутбуке.
2. В настройках проекта указать существующую локальную папку репозитория.
   Клонирование пока выполняется в VS Code/Git: Контур не загружает код автоматически.
3. Установить официальные Codex CLI, Claude Code и GitHub CLI. В разделе
   «Подключения» нажать «Войти» для нужного инструмента; используется штатный вход
   в браузере. Подписки и доступность проверяет поставщик. Ключи API не требуются
   при доступном пользователю входе по подписке.
4. Назначить роли в проекте, включить «Выполнять очередь на этом ноутбуке».
5. В общем чате выбрать участника или цепочку: руководитель → разработчик → проверка.

Codex запускается через `codex exec --json --sandbox ... -`; Claude через
`claude -p --output-format json --max-turns 30`. Контекст идёт через stdin,
shell-интерполяции нет. Руководитель и проверяющий имеют только чтение;
разработчик получает разрешения на правки; роль публикации использует те же
инструменты, но публикация должна быть прямо запрошена задачей. Ограничения
официальных CLI не отключаются; для недоступных операций показывается ошибка.
Общий чат хранит итоговые ответы, не скрытые рассуждения моделей.
Лимит одного шага — 30 минут, вывод — 8 МБ. Сбой не вызывает автоматический повтор.

## Облачная версия на текущем сайте

Flask-регистрация в `app.py` добавляет `/kontur/`. Доступ только для пользователя
с ролью `admin` в существующей сессии сайта. Клиентские кабинеты не получают доступ.
Данные находятся в `DATA_DIR/kontur/kontur.sqlite3`, отдельно от базы сайта.
Не требуются новая БД, отдельный сервер, новые API-подписки или домен.

Установку выполняет `kontur/deploy.py` на существующем сервере. Он проверяет
форму кода, создаёт копию изменяемых файлов, точечно добавляет регистрацию
Контура и исключение из старой form-CSRF проверки; на маршрутах Контура работает
его собственная проверка JSON CSRF / ключа устройства. Старый код сайта и
«Прораб+» не заменяется веткой целиком. Перезапуск — через Passenger restart.txt.
Запуск сначала с `--check`, затем без него. При отличающемся коде останавливается.

```sh
~/metalcarcase-production/.venv/bin/python kontur/deploy.py --production "$HOME/metalcarcase-production" --webroot "$HOME/www/metalcarcase.ru" --check
~/metalcarcase-production/.venv/bin/python kontur/deploy.py --production "$HOME/metalcarcase-production" --webroot "$HOME/www/metalcarcase.ru"
```

На сайте войти владельцем → `/kontur/` → «Подключения» → создать ключ ноутбука.
Вставить ключ в приложение на Windows. Ключ виден один раз, хранится на сервере
только как SHA-256, на Windows защищён DPAPI. Доступ устройства можно отозвать.
Ключ никогда не включается в синхронизацию, экспорт или Git.

## Синхронизация и выполнение

Ноутбук каждые 10 секунд отправляет изменённые записи и получает облачные.
Локальные правки работают без интернета. CAS по UUID-ревизии предотвращает
молчаливое затирание; конфликты сохраняют обе версии, доступны варианты
«локальная / облачная / обе». Удаления — tombstone. После обрыва повтор передачи
идемпотентен. Правка во время HTTP-запроса остаётся в очереди следующей передачи.

Облачные задания выполняются только подключённым ноутбуком с включённой очередью.
Перед стартом парный ноутбук атомарно получает право на выполнение на сервере.
Если связи нет, новые ИИ-запуски в парном режиме ждут её; локальные данные доступны.
После закрытия программы незавершённые запуски помечаются «Прервано».
Остановка из облака приходит после следующей связи — это не мгновенная аварийная кнопка.

## Резервные копии

Экспорт JSON: только записи, без ключей и путей. Импорт валидирует весь пакет,
сохраняет копию SQLite и создаёт новые записи с новыми ID. Незавершённые задания
из копии не выполняются автоматически. Данные не удаляются деинсталлятором.

```sh
python -m unittest discover -s kontur/tests -v

```

## Границы первой версии

Нет переноса прошлых чатов ChatGPT/Claude, автоматического выбора моделей,
встроенного редактора кода, фонового облачного вычислителя и автоматического
клонирования репозиториев. Роли и общий чат реализованы поверх официальных CLI.
Реальный вход и запуск с подписками необходимо проверить на ноутбуке владельца.
Установщик пока без сертификата Authenticode; Windows может показать предупреждение
SmartScreen. GitHub Windows CI проверяет запуск бинарного файла; это не заменяет
проверку GUI и авторизаций на целевой Windows 11 23H2.
